01 — Field notes

How it works

Note 01The problem3 min read

Your dapp talks to strangers.

One balance check can leak your IP, wallet and app.

Read the note

A dapp can make blockchain reads directly from the page with its own RPC provider. An eth_getBalance call carries your address in its parameters, your IP in the connection, and the app’s identity in a provider URL or project key.

Analytics and application APIs can receive the address too. Agents have the same problem: their reads, API calls and LLM prompts can reveal the wallets they operate.

Note 02Enforce

Reads go over Tor.

The RPC sees an exit relay, not you.

Read the note

For standard reads on a supported chain, Canary sends the call to its own read endpoint through anon-rpc and tor-js. The dapp’s provider never receives that read.

Non-standard methods are forwarded to the original URL over the same path: your IP is hidden, but the provider URL still identifies the app, so these count as IP only.

Each watched wallet gets its own circuit key, addr:<address>. Reads batch in a 15 ms window, and a stalled read retries on a fresh circuit after 3 seconds.

Note 03Block

Leaks stop at the edge.

Trackers carrying your wallet are blocked.

Read the note

Canary wraps the page’s fetch, XHR and WebSocket at load. Requests to third parties that contain a watched address are refused; browser rules also catch tracking pixels.

Matching is exact: plain, checksummed, padded and supported base64 forms. Hashed or encrypted addresses can slip past, and bodies Canary can’t read are labelled Not inspected.

Note 04Measure

Every request counted.

Gaps included, never hidden.

Read the note

Categories include Protected, IP only, Blocked, Detected, Backend, Not inspected, Failed closed, Direct and Local node. Not inspected is never counted as protected.

If the private route fails, the request returns an error and counts as Failed closed, unless you turn on direct fallback for that site. A zero-leak result applies only to the channels Canary inspected and the flow you exercised.

Note 05Agents

Agents follow a policy.

Wallets become aliases before the LLM.

Read the note

The local gateway exposes a JSON-RPC endpoint and an HTTP proxy. Its policy comes from the agent’s privacy.manifest ENS record; undeclared hosts are blocked by default.

The SDK plugs into viem or ethers. llmFetch swaps wallets for WALLET_1 and the agent’s name for AGENT_NAME, keeps amounts unchanged, and restores aliases before tools run.

03 — Get Canary

Get Canary

Browser extension

Works on any dapp. No changes needed.

Get extension
  1. Build: cd extension && npm install && npm run build
  2. Open Chrome’s Extensions page and turn on Developer mode.
  3. Load extension/dist, then reload your dapp tabs.
